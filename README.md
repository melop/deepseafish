  
The project is organized into numbered directories, each representing a distinct analysis step. 

# 1. System Requirements 
 - **Operating System**: A Linux-based OS is required. The scripts have been tested on CentOS 7 and Ubuntu 18.04+. 
 * **Hardware**: These analyses are computationally intensive and **cannot be run on a standard desktop computer**. 
 * **Environment**: A High-Performance Computing (HPC) cluster with a job scheduler like Slurm is strongly recommended. Many scripts are written as `.sbatch` jobs. 
 * **RAM**: >128 GB is required for genome assembly (`03.NextDenovo`, `04.Flye`) and annotation (`09.Funannotate`). 
 * **CPU**: >32 cores are recommended to accelerate most steps.
 * **Storage**: A multi-terabyte storage solution is necessary to hold the raw data, intermediate files, and final results. 
 * **Software Dependencies**: This project relies on a large number of bioinformatics tools. The specific versions used are often noted in the scripts. It is **highly recommended to use a package manager like Conda/Bioconda** to manage these dependencies. Key software includes: 
 * **Sequencing Tools**: `Trimmomatic` (v0.39), `BWA` (0.7+), `Samtools` (1.9+), `GATK` (4.2+) 
 * **Assemblers**: `NextDenovo` (v2.5.0), `Flye` (2.9+), `SGA`, `Trinity` 
 * **Annotation**: `BUSCO` (v5+), `Funannotate` (1.8+), `RepeatModeler`, `RepeatMasker` 
 * **Comparative/Evolutionary**: `OrthoFinder` (2.5+), `PAML` (v4.9j - codeml, mcmctree), `Hyphy` (RELAX), `RAxML` (8.2+), `CAFE` (v5), `Minimap2` (2.20+) 
 * **Population Genomics**: `PSMC`/`MSMC2` (2.1+), `ROHan` (1.0+) 
 * **Scripting**: `Bash`, `Python 3`, `Perl`, `PHP`, `R` (4.1+)

## 09.Funannotate
This is a complete genome annotation pipeline, from genome cleaning and repeat analysis to the final gene prediction.

**Sub-dir 01: Clean Genome**
-   **Purpose**: `funannotate clean` removes contigs that are too short or have abnormal coverage; `funannotate sort` sorts and renames contigs.
-   **Input**: `pachycara.fasta` (raw assembly).
-   **Output**: `pachycara_sort.fa` (cleaned & sorted genome).

**Sub-dirs 02 & 03: Repeat Modeling & Masking**
-   **Purpose**:
    1.  `02.repeatmodeler.sh`: Build a species-specific repeat library from scratch (*de novo*) using RepeatModeler.
    2.  `03.joinlib.sh`: Combine the custom library with a known one from related species (Repbase).
    3.  `03.repeatmasker.sbatch`: Use RepeatMasker to find these repeats in the genome and soft-mask them (i.e., convert repeat bases to lowercase).
-   **Input**: `pachycara_sort.fa`.
-   **Output**: `scf.softmasked.fa` (soft-masked genome), `all_te.fa` (the final repeat library).

**Sub-dir 04: Gene Annotation (Funannotate - Main Pipeline)**
-   **Purpose**: A multi-step process to train models and predict genes.
    1.  `1_train.sbatch`: Train gene prediction models (PASA/Augustus) using RNA-seq data and Trinity transcripts.
    2.  `predict.sbatch`: Predict gene structures using the trained models, protein homology evidence, etc.
    3.  `update.sbatch`: Further update the predictions with PASA to add UTRs and alternative splicing info.
-   **Input**:
    -   `pachycara_scf.softmasked.fa` (soft-masked genome).
    -   RNA-seq reads (`left.fq.gz`, `right.fq.gz`).
    -   Trinity transcripts (`pachycara_combtrinity_cdhit.fa`).
    -   Homologous protein sequences (`all.prot.fa`).
-   **Output**: The `trained_2/` directory, containing all annotation results (GFF3, GBK files, etc.).

**Sub-dir 05: Gene Annotation (Funannotate - Miniprot Pipeline)**
-   **Purpose**: An alternative annotation pipeline to `04`. The main difference is the use of `miniprot`-assisted transcripts as evidence (`joined_miniprot_trinity.trans.fasta`). The other steps (train, predict, update) are similar to `04`.
-   **Input**: Same as above, but the `Trinity` evidence is replaced by the `miniprot`-related transcripts.
-   **Output**: The `trained_1/` directory, containing the final annotation results from this pipeline.

## 10.genewise
This is a homology-based gene prediction pipeline, featuring two parallel workflows: a detailed GeneWise process and a rapid MetaEuk process.

-   **Purpose (Overall Workflow)**:
    1.  **Data Prep (`1_preBlast` & `2_tblastn`)**:
        -   Pre-processes protein families from OrthoFinder (filters outliers, aligns with MAFFT).
        -   Maps the processed proteins to the genome using `tblastn` to find homologous regions.
    2.  **GeneWise Input Prep (`3_preGenewise`)**:
        -   Uses `bedtools` to process `tblastn` hits: merge, extend (slop) regions, and extract the corresponding genomic DNA.
        -   Concurrently, builds an HMM profile for each protein family using `hmmbuild`.
    3.  **Prediction & Collection (`4_rungenewise` & `5_GetGenewiseFa`)**:
        -   Runs `genewise` in a large-scale parallel manner, using the HMM profiles for precise gene structure prediction on the target DNA regions.
        -   Finally, collects all predicted cDNA sequences into a single file.
    4.  **Complementary Prediction (`6_metaeuk` & `7_changeDup`)**:
        -   (Optional) Runs `metaeuk` for a supplementary, rapid gene prediction.
        -   (Optional) Renames headers in the final Fasta file to ensure unique IDs.
-   **How-to**:
    1.  Submit the Slurm scripts in order: `sbatch 1_pre*.sbatch`, `sbatch 2_*.sbatch`, `sbatch 3_*.sbatch`, `sbatch 4_*.sbatch`.
    2.  After the jobs complete, run `python3 5_GetGenewiseFa.py` to collect the GeneWise results.
    3.  Run `6_metaeuk.sbatch` and `7_changeDup2.py` as needed.
-   **Input**:
    -   Orthologous protein sequences (`*.fa`) from OrthoFinder.
    -   `scf.softmasked.fa`: The target genome.
-   **Output**:
    -   `allout.fa`: All cDNAs predicted by GeneWise.
    -   `result/`: The output directory from MetaEuk.
    -   `comb_dedup.fa`: The Fasta file with renamed headers.

## 12.Hyphy
**Sub-dir 01: GENESPACE**
-   **Purpose**: To perform large-scale genome synteny and orthology analysis across multiple species using the `GENESPACE` R package.
-   **Workflow**:
    1.  The `prep_funannotate_genome.sh` script first runs a PHP script to convert Funannotate's protein output (`*.longest_isoform.prot.fa`) into the GFF and peptide formats required by GENESPACE.
    2.  The `runR.sh` script then executes the core R script (`run.R`), which automates OrthoFinder and MCScanX runs to identify orthogroups and syntenic blocks across genomes.
-   **Input**: `*.longest_isoform.prot.fa` files from multiple species.
-   **Output**: The `rundir/` directory, containing OrthoFinder results and genome-wide synteny maps.

**Sub-dir 02: Assign Gene Symbols**
-   **Purpose**: To annotate the orthogroups identified by OrthoFinder (in the `01_genespace` step) with human-readable gene symbols (e.g., 'sox9', 'hoxb5').
-   **Workflow**:
    1.  First, the `make_genesymbol_table_*.php` scripts parse GFF files from various species (Ensembl or NCBI format) to create mapping files (`*.map.txt`) between gene IDs and gene symbols.
    2.  Then, `assigngenesymbol_orthofinder.php` reads the OrthoFinder output and these map files, assigning a consensus gene symbol to each orthogroup based on a voting system.
-   **Input**:
    -   OrthoFinder results (`N0.tsv`).
    -   GFF annotation files for multiple species.
-   **Output**: `orthofinder_genesymbols.tsv`, an orthogroup table annotated with gene symbols.

**Sub-dir 03: Other Species Protein 
-   **Purpose**: To clean and consolidate protein sequences from various sources (esp. NCBI) in preparation for downstream analyses.
-   **Workflow**:
    -   The core script is `preprocessAA.php`, whose main function is to select only the **longest protein isoform** for each gene. This is a standard practice to remove redundancy and simplify analyses.
    -   The `prepareNCBIProteins.sh` script batch-processes multiple species and uses `minreID.py` to standardize sequence IDs.
-   **Input**: Raw protein FASTA files containing all isoforms.
-   **Output**: Cleaned protein files (`*.filtered.fa`) and a combined protein database (`allNCBIproteins.fa`).

**Sub-dir 04: ExportAln Genespace**
-   **Purpose**:
    1.  **Generate Codon Alignments (`exportAln*`, `genespace2*`)**:
        -   `genespace2orthologtable.php` first consolidates the GENESPACE results into a clean ortholog table (`genespace.orthogroups.txt`).
        -   `exportAln_multiref_withorigseq.php` is the main workhorse. It iterates through this table, extracts the CDS sequences for every species in each orthogroup.
        -   It then uses `TranslatorX` (an external tool, used implicitly) to create codon alignments guided by the protein alignment—a crucial step for high-quality results. The whole process is parallelized via `export.local.sh`.
    2.  **Phylogenetic Congruence Test (`monophyly_test*`)**:
        -   This is a strict quality control (QC) step. For each gene alignment, a gene tree is built (`RAxML`).
        -   An AU test is then performed to check if the gene tree's topology conflicts with the expected species tree topology.
        -   Genes that significantly conflict with the species tree (which could indicate bad ortholog calls or alignment errors) are **filtered out**. `remove_non_monophyly.sh` handles the removal of these rejected genes.
    3.  **Label Tree Branches (`labelbranches*`)**:
        -   This is the final preparation step. The `labelbranches.R` script takes the gene trees that passed QC.
        -   Based on user specifications (e.g., "I want to study the deep-sea fish `Pachycara`"), it annotates each tree to mark "foreground branches" (the branches to be tested) and "background branches".
        -   Scripts like `labelbranches.all.sh` are launchers for running different hypotheses (i.e., testing different species/clades).
-   **Input**:
    -   Outputs from `01_genespace` & `02_assigngenesymbols`.
    -   Species' GFF and genome files.
    -   A config file defining the species phylogeny (`monophyly_desc.txt`).
-   **Output**:
    -   `output/` dir: Contains the codon alignment file for all species (`ret_improved_cleanDNA.fasta`).
    -   `Relax_Pachy/`, `Codeml_Basso/`, etc.: Each directory represents a specific evolutionary hypothesis. They contain the **branch-labeled tree files** for each gene. These, along with the alignment file, are the final inputs for Hyphy RELAX or PAML CodeML.

**Sub-dir 05: RAxML 
-   **Purpose**: The scripts here use the alignments of all orthologous genes from the previous steps to build a robust species phylogenetic tree using a supermatrix (concatenation) approach.
-   **Workflow**:
    1.  Run `php convert2phylip.php`. This script reads the main codon alignment file (`ret_improved_cleanDNA.fasta`) from the previous step.
    2.  It concatenates all gene sequences for each species into a single super-sequence and generates PHYLIP-formatted files based on three different partitioning strategies:
        -   `full.phy`: Contains all codon positions.
        -   `codon12.phy`: Contains only the 1st and 2nd codon positions, reflecting amino acid changes.
        -   `syn.phy` (or `4fold.phy`): Contains only 4-fold degenerate sites, often used as a proxy for neutral evolution.
    3.  Rename or link one of the resulting `.phy` files to `in.phy`.
    4.  Execute `bash raxml.sh` to build the Maximum Likelihood (ML) phylogenetic tree, including 100 bootstrap replicates.
-   **Input**:
    -   `../ret_improved_cleanDNA.fasta`: The final codon alignment file from the `04_exportAln_genespace` directory.
-   **Output**:
    -   `phylipformat/` directory: Contains the `full.phy`, `codon12.phy`, `syn.phy` files.
    -   `RAxML_bestTree.allcodons`: The best-scoring ML tree.
    -   `RAxML_bootstrap.allcodons`: The tree file annotated with bootstrap support values.

**Sub-dir 06: RELAX Analysis
-   **Purpose**:  It uses Hyphy RELAX to test whether coding genes across the genome have experienced widespread relaxation or intensification of natural selection on the predefined "foreground" branches (e.g., `Bassozetus_sp`).
-   **Workflow**:
    1.  The `hyphyrelax.php` script is the main driver, typically executed in parallel.
    2.  For each orthologous gene that passed all previous QC steps, the script combines its codon alignment with its corresponding branch-labeled tree file.
    3.  It then automatically invokes the HYPHY-RELAX program (`RELAX.bf`) to perform the statistical analysis.
    4.  After all jobs are complete, the `summary.sh` script is used to consolidate the outputs. It gathers all successful results, sorts them by significance (p-value), and also lists any genes that failed the analysis.
-   **Input**:
    -   `04_exportAln_genespace/ret_improved_cleanDNA.fasta`: The final codon alignment file.
    -   `04_exportAln_genespace/Relax_Basso/`: The directory containing the corresponding branch-labeled tree for each gene.
-   **Output**:
    -   `sum_Basso.txt`: The final summary table of results. It is sorted by p-value, with each row representing a gene and columns containing key RELAX metrics (the K-value, p-value, dN/dS distributions for test vs. reference branches, etc.). This file is ready for downstream interpretation and candidate gene selection.
    -   `sum_Basso_err.txt`: A list of genes for which the analysis failed.

## 13.MSMC
This directory contains a full MSMC2 (Multiple Sequentially Markovian Coalescent) pipeline to infer the historical effective population size of a species from a single diploid individual's whole-genome resequencing data.

-   **Purpose**:
    -   To reconstruct the population size fluctuations of a species over the last hundred thousand to several million years.
-   **Workflow**:
    1.  **Data Mapping (Scripts 1-5)**: Use `bwa` to align short reads to the reference genome, followed by standard sorting, duplicate removal, and indexing to prepare a clean BAM file.
    2.  **Generate Input Files (Scripts 6-7)**: Use `bamCaller.py` and `generate_multihetsep.py` from `msmc-tools` to process the BAM file and create the required MSMC2 input files (`*.multihetsep.txt`) for each chromosome.
    3.  **Run MSMC2 (Script 8)**: Combine the input files from all chromosomes and run the main `msmc2` program to get the initial demographic history curve.
    4.  **Bootstrapping (Scripts 9-10)**: To assess statistical confidence, `multihetsep_bootstrap.py` is used to resample the genome, creating multiple (30 in this case) bootstrap datasets. MSMC2 is then re-run on each of these.
    5.  **Visualization (Script 11)**: An R script (`plotting.R`) is used to plot the main result and overlay the 30 bootstrap results on a single graph, generating the final demographic history plot.
-   **How-to**:
    -   This is a strictly linear pipeline. The scripts **must be executed in numerical order (1 -> 11)**.
-   **Input**:
    -   `pachycara_chr.fasta`: A chromosome-level reference genome.
    -   `pachycara.paired_*.fq.gz`: Clean, paired-end short reads.
-   **Output**:
    -   `pachycara_chr.pdf`: The final demographic history plot, where the solid line is the best estimate and the transparent lines are the bootstrap replicates.
    -   `msmc2ret/` & `bootstrapped/`: Directories containing all the raw computational results.

## 15.MCMCTree
The scripts in this directory use the `MCMCTree` program from the PAML package to estimate species divergence times using a molecular clock and fossil calibrations.

-   **Purpose**:
    -   To infer the absolute divergence times for nodes on a species tree, based on multi-locus sequence data and fossil records.
-   **Workflow**:
    1.  **Prepare Sequence File (`partition_codonpos.php`)**: This script converts the concatenated PHYLIP file (`full.phy`) into the MCMCTree input format. It partitions the alignment by splitting the 1st, 2nd, and 3rd codon positions into three separate blocks, as they evolve at different rates.
    2.  **Prepare Tree File (`pre_tree.py`)**: This script converts a standard Newick tree file into the simplified topology format required by MCMCTree.
    3.  **Approximate Likelihood Calculation (`gtr_approx01/`)**:
        -   `mcmctree_make.in.BV.ctl` (run via `make.in.bv.sh`) is used to estimate the gradient and Hessian matrix, a crucial step that dramatically speeds up the subsequent MCMC sampling.
        -   `mcmctree.ctl` (run via `approx.sh`) performs the main MCMC analysis.
    4.  **Summarize & Final Run (`sum.sh`)**: This script consolidates the results from multiple independent MCMC runs (`gtr_approx01` to `gtr_approx04`). By combining the posterior samples from several runs, it allows for better convergence diagnostics and yields more robust divergence time estimates.
-   **Input**:
    -   `full.phy`: The concatenated multi-locus PHYLIP file.
    -   A species tree in Newick format (e.g., `rerooted.tre`).
    -   `mcmctree.ctl`: The main configuration file for MCMCTree, which specifies fossil calibrations and other critical parameters (this file is not provided).
-   **Output**:
    -   `FigTree.tre` (typically generated in the final analysis directory): The final output tree containing node ages, confidence intervals, etc., ready for visualization in programs like FigTree.
    -   `mcmc.txt`: The raw MCMC log file, containing the posterior distributions for all parameters.

## 16.Paml
The scripts in this directory are set up to run `codeml` from the PAML package to calculate dN/dS (the ratio of non-synonymous to synonymous substitution rates) and test for selection pressures along different evolutionary lineages.

-   **Purpose**:
    -   To use branch models to test whether specific lineages on a phylogeny have experienced different selection pressures (e.g., accelerated evolution or purifying selection) compared to others.
-   **Workflow**:
    1.  **Prepare Sequences (get\_\*.sh)**: This is an interesting preprocessing workflow. It first uses `bcftools consensus` with a VCF file to generate two haplotype "pseudo-genomes" for a single individual (`pachycara`). Then, it uses `gffread` to extract the corresponding CDS from these personalized genomes. The goal is to get accurate allele sequences for this species to include in the broader multi-species alignment.
    2.  **Format Conversion (`convert2phylip.php`)**: This PHP script converts a multi-species codon alignment from FASTA format into the PHYLIP format required by PAML.
    3.  **Run Analysis (`run_codeml.sh`)**: This is a simple wrapper script that executes `codeml` using the parameters defined in the `codeml.ctl` file.
-   **Input**:
    -   `codeml.ctl`: The main PAML control file where the analysis model (branch model), data paths, etc., are specified.
    -   `full2.phy`: The PHYLIP-formatted multi-species codon alignment (generated by `convert2phylip.php`).
    -   `tree.txt`: A species tree file (Newick format) with branches labeled for testing.
    -   (Inputs for preprocessing): A reference genome, VCF file, and GFF annotation file.
-   **Output**:
    -   `out`: The main results file from `codeml`. It's a detailed text file containing dN/dS ratios for the tested branches, LRT test statistics for model comparisons, and other information.

## 17.rohan
The scripts in this directory use the ROHan software to analyze Runs of Homozygosity (ROH) and heterozygosity within an individual's genome.

-   **Purpose**:
    -   To identify ROH regions in the genome, which can reflect a history of inbreeding or population bottlenecks.
    -   To estimate genome-wide heterozygosity in sliding windows.
-   **Workflow**:
    1.  **BAM Filtering (`00bam/Q30_filter.sh`)**: A standard QC step using `samtools` to filter out low-quality alignments (MAPQ < 30).
    2.  **Run ROHan (`run_rohan.sh`)**: Executes the main ROHan program on the filtered BAM files to perform ROH calling and heterozygosity estimation.
    3.  **Summarize Heterozygosity (`stats_het.sh`)**: Parses the ROHan output files (`*.hEst.gz`) to calculate the average heterozygosity for each sample, summarizing the results in `part3.filtered.het.txt`.
-   **Input**:
    -   Deduplicated BAM alignment files (`*.dedup.bam`).
    -   Reference genome (`pachycara.softmasked.fa`).
-   **Output**:
    -   `part3.filtered.het.txt`: A summary file containing the average heterozygosity for each sample.
    -   A results directory for each sample (e.g., `pachycara/`) containing detailed outputs from ROHan, such as `*.hEst.gz` (heterozygosity estimates) and ROH coordinates.

## 18.PNPS
The scripts in this directory are designed to calculate the pN/pS ratio (the ratio of non-synonymous to synonymous polymorphisms) within a population, a key metric for measuring population-level selection pressure.

-   **Purpose**:
    -   To extract SNPs from a VCF file and functionally annotate them (as synonymous, missense, etc.) using SnpEff.
    -   To count the numbers of pN and pS sites and calculate their ratio.
    -   (Optional workflow) To generate "pseudo-genomes" from VCF files for multiple individuals and extract alignments for other analyses.
-   **Workflow**:
    1.  **SNP Annotation (`snpeff.sh`)**:
        -   First, `bcftools` is used to strictly filter the raw VCF file, retaining only high-quality SNPs.
        -   Then, `SnpEff` is run to functionally annotate these SNPs, identifying them as synonymous, missense, or other variant types.
    2.  **Calculate pN/pS (`count_pN_pS.sh`)**:
        -   This script directly parses the SnpEff-annotated VCF file.
        -   It counts the number of missense (pN) and synonymous (pS) variants separately.
        -   Finally, it calculates the pN/pS ratio.
    -   **Input**:
    -   `pachycara.genotyped.g.vcf.gz`: A VCF file containing population SNP data.
    -   An SnpEff database built for the reference genome (e.g., `pachycara_1.0`).
-   **Output**:
    -   The pN/pS ratio (printed directly to the screen).
    -   `pachycara.filter.snp.snpeff.vcf.gz`: The SnpEff-annotated VCF file.

## 19.CAFE
The scripts in this directory use the CAFE5 software to analyze the expansion and contraction of gene families across species evolution.

-   **Purpose**:
    -   Based on a given species tree and the size of gene families in each species, infer where on the phylogeny significant gene family expansion or contraction events occurred.
-   **Workflow**:
    1.  **Data Prep (`convert_*.sh`, `modifyTree.sh`)**:
        -   Converts the OrthoFinder gene count table (`Orthogroups.GeneCount.tsv`) into the required CAFE input format.
        -   Cleans the species tree file (`FigTree.tre`) by removing unnecessary characters.
    2.  **Error Model Estimation (`err.est.sh`)**: The first step in running CAFE is to estimate an error model. This is important to correct for gene count inaccuracies that may arise from imperfect genome annotations.
    3.  **Model Selection (`runk2.sh` to `runk6.sh`)**:
        -   To find the best evolutionary model for the data, the scripts run CAFE with different numbers of gene family evolution rate categories (gamma categories, k=2 to 6).
        -   Each `k` value is run 20 times to ensure the results are robust.
    4.  **Summarize Results (`stats.sh`)**: Gathers the likelihood scores from all model runs. This is used later to compare models and select the best `k` value for final interpretation.
-   **Input**:
    -   `Orthogroups.GeneCount.tsv`: The gene family count table from OrthoFinder.
    -   `FigTree.tre`: An ultrametric species tree.
-   **Output**:
    -   `runresults_k*/`: Output directories for each `k`-value run.
    -   `stats.txt`: A statistical summary for model comparison.
    -   The key final output (found within the directory of the best `k` value): A report detailing which gene families have changed size significantly on each branch of the phylogenetic tree.

## 20.GENE_LOSS
This is a complex, multi-step pipeline designed to identify lost genes in two target species (`Pachycara` and `Bassozetus`) and to follow up with functional and synteny analyses.

-   **Purpose (Overall Workflow)**:
    1.  **Ortholog Identification (Sub-dirs 00-03)**:
        -   Similar to previous pipelines (#12), this starts by pre-processing GFF and protein files for all species, then uses `GENESPACE` to perform a large-scale ortholog identification across 23 species. This forms the basis for all subsequent comparisons.
    2.  **Gene Loss Identification & Visualization (Sub-dirs 04-05)**:
        -   **The Core Step**: The `select_unloss.sh` script compares the list of genes actually found by GENESPACE (`*_unloss.txt`) against a pre-existing list of *suspected* lost genes (`*_geneloss_orig.txt`). Genes that are still absent are deemed **"confirmed losses"** (`*_loss_confirmed.txt`).
        -   `plot_venn.R` then visualizes these "confirmed losses" for the two species in a Venn diagram to show shared and species-specific losses.
    3.  **Functional Analysis (Sub-dir 06)**:
        -   To understand what the lost genes *do*, this step runs a smaller `GENESPACE` analysis comparing the target species to model organisms (Zebrafish, Human). The goal is to find the orthologs of the lost genes in these well-annotated species, which enables GO (Gene Ontology) enrichment analysis.
    4.  **Synteny Validation (Sub-dir 07)**:
        -   This is a case study focusing on a single candidate gene (`cart4`). The scripts extract this gene and its genomic neighbors, then examine the conservation of gene order (synteny) in this region across multiple species. If the neighboring genes are conserved but the target gene is missing, it provides very strong evidence for a true gene loss event.
-   **Input**:
    -   GFF and protein FASTA files for all species.
    -   A pre-existing list of suspected lost genes (`*geneloss_orig.txt`).
-   **Output**:
    -   `pachycara_loss_confirmed.txt`, `Bassozetus_loss_confirmed.txt`: The final lists of confirmed lost genes.
    -   A Venn diagram image showing the overlap of lost genes.
    -   A synteny plot for the `cart4` gene region.

## 22.minimap
This script (`aln.sh`) uses `minimap2` to perform a whole-genome alignment between two closely related species (`Bassozetus` and `Brotula`).

-   **Purpose**:
    -   To quickly align two assembled genomes to identify large-scale structural variations (SVs) and small variants (SNPs/Indels) between them.
-   **Workflow**:
    1.  `minimap2` generates a raw alignment file in PAF format.
    2.  `paftools` (a companion tool to minimap2) parses this PAF file to "call" the differences between the two genomes, outputting them in VCF format.
-   **How-to**:
    1.  Modify the `genome1`, `genome2`, and other variables at the top of the script to point to your genome files.
    2.  Just run `bash aln.sh`.
-   **Input**:
    -   `Basso.softmasked.fa` (Reference Genome)
    -   `Bmul.softmasked.fa` (Query Genome)
-   **Output**:
    -   `pairwise.aln.*.paf`: The raw whole-genome alignment file.
    -   `out.*.vcf.gz`: A VCF file containing all variant sites (SNPs, Indels, SVs) between the two genomes.

## 23.BWA_GATK
This is a standard BWA + GATK "Best Practices" pipeline for accurately calling SNPs (Single Nucleotide Polymorphisms) and Indels (Insertions/Deletions) from whole-genome resequencing data for a single sample.

-   **Purpose**:
    -   To perform high-quality germline variant discovery for an individual sample.
-   **Workflow**:
    1.  **Alignment (`bwa.sh`)**: Uses `bwa mem` to align the raw short reads to the reference genome, producing a sorted BAM file.
    2.  **GATK Pre-processing (`gatk.sh` - Steps 2-3)**:
        -   `AddOrReplaceReadGroups`: Adds essential metadata tags to the BAM file.
        -   `MarkDuplicates`: Identifies and flags duplicate reads arising from PCR, reducing false positives.
    3.  **Variant Calling (`gatk.sh` - Steps 4-7)**:
        -   `HaplotypeCaller`: The core GATK tool, run in `GVCF` mode, to perform haplotype-based calling and generate an intermediate file (`.g.vcf`).
        -   `GenotypeGVCFs`: Converts the GVCF file into a final VCF file, completing the genotyping for all sites.
    4.  **Automated Execution (`do_gatk.sh`)**: A convenient wrapper script that automatically launches the `gatk.sh` pipeline for every BAM file found in the directory.
-   **Input**:
    -   `*.paired_1.fq.gz` & `*.paired_2.fq.gz`: Raw, paired-end sequencing reads.
    -   `pachycara_sort.fa`: The reference genome.
-   **Output**:
    -   `*.genotyped.g.vcf.gz`: The final variant call file for each sample, containing high-quality SNPs and Indels.
    -   `*.dedup.bam`: The analysis-ready BAM file after pre-processing, which can be used for other analyses.
